# Бюджетная стереосистема — StereoBM и CREStereo

Проект на Python и OpenCV для калибровки двух камер, ректификации изображений и оценки расстояния классическим методом **StereoBM** и нейросетевым методом **CREStereo** с вычислением на GPU. Предусмотрены локальная обработка на Windows и Linux / Raspberry Pi и экспериментальная схема удалённой обработки: камеры подключены к Raspberry Pi, а StereoBM либо CREStereo выполняются на ноутбуке через SSH-туннель.

Программа показывает изображения камер и карту диспаратности, измеряет расстояние в небольшой области кадра и сохраняет статистику экспериментов в CSV.

## Возможности

- Определение индексов подключённых камер.
- Сохранение пар фотографий шахматной доски.
- Калибровка каждой камеры и стереопары.
- Ректификация: выравнивание соответствующих точек по горизонтали.
- Численная проверка вертикального расхождения по углам шахматной доски.
- Измерение расстояния по медиане диспаратности в области 31 × 31 пиксель.
- Сбор 50 валидных измерений с расчётом среднего, стандартного отклонения и ошибки относительно заданного расстояния.
- Вывод скорости обработки и времени отдельных этапов.
- Передача стереопар с Raspberry Pi на ноутбук по JPEG/TCP через SSH-туннель (экспериментальные отдельные скрипты).
- Сравнение StereoBM на CPU и CREStereo на GPU при локальном и удалённом захвате.

## Требования и установка

Нужны Python 3, NumPy, OpenCV с поддержкой графических окон, две камеры и шахматная доска. Для Linux используется интерфейс V4L2. Для просмотра окон требуется графическая сессия; пакет opencv-python-headless для этих сценариев не подходит.

Зависимости перечислены в requirements.txt.

### Windows

Откройте PowerShell в распакованной папке Stereo_BM:

```powershell
py -m venv .venv
./.venv/Scripts/python.exe -m pip install numpy opencv-python
cd stereo_project_win
../.venv/Scripts/python.exe camera_index_check.py
```

В командах ниже под python понимается интерпретатор этого окружения. Без активации окружения используйте вместо python путь ..\.venv\Scripts\python.exe.

### Linux / Raspberry Pi

Откройте терминал в распакованной папке Stereo_BM:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install numpy opencv-python
cd stereo_project_lin
python camera_index_check_linux.py
```

Доступность готового пакета OpenCV зависит от ОС, архитектуры и версии Python. Если установка не проходит, потребуется совместимая сборка OpenCV для вашей системы.

**Выполняйте дальнейшие команды из папки своей платформы.** Многие скрипты читают и записывают файлы относительно текущей рабочей папки.

## Порядок работы

### 1. Определите камеры и согласуйте их порядок

Закройте другие программы, использующие камеры, и запустите camera_index_check.py либо camera_index_check_linux.py. Скрипт проверяет индексы от 0 до 5. Поочерёдно закрывайте объективы, чтобы определить физическую левую и правую камеры.

- Пробел — следующая камера.
- Q или Esc — завершить проверку.

### 2. Снимите калибровочные пары

В stereo_calibrate.py или stereo_calibrate_linux.py проверьте:

```python
CHECKERBOARD = (9, 6)
SQUARE_SIZE = 24.0  # миллиметры
```

9 × 6 — количество **внутренних углов**, то есть доска из 10 × 7 клеток. SQUARE_SIZE должен соответствовать фактически измеренной стороне клетки. От этого зависит масштаб вычисляемого расстояния.

Запустите скрипт своей платформы:

```powershell
# Windows
python capture_calibration.py
```

```bash
# Linux
python capture_calibration_linux.py
```

Нажимайте S, чтобы сохранить пару, и Q для выхода. Снимки записываются как calibration_photos/left/00.jpg и calibration_photos/right/00.jpg, затем 01.jpg и т. д.

Снимайте доску в разных положениях, наклонах и частях кадра; она должна быть видна обеим камерам. Для продолжения калибровки код требует минимум 10 пар с обнаруженными углами на обоих изображениях.

**При каждом запуске нумерация начинается с 00: существующие снимки с такими именами перезаписываются.** Перед новой серией перенесите предыдущие снимки в отдельную папку. Имена и порядок файлов слева и справа должны соответствовать: калибратор сопоставляет отсортированные списки файлов.

Сохраняйте одинаковое разрешение камер при съёмке, ректификации и измерении. Скрипты съёмки и просмотра ректификации не задают разрешение явно; при необходимости добавьте его настройку в код.

### 3. Выполните калибровку

```powershell
# Windows
python stereo_calibrate.py
```

```bash
# Linux
python stereo_calibrate_linux.py
```

Скрипт выводит ошибки калибровки, матрицы камер, взаимный поворот R, перенос T и расчётное расстояние между оптическими центрами камер. Результат сохраняется в stereo_calibration.npz, заменяя существующий файл.

Файл содержит K_left, D_left, K_right, D_right, R, T, E, F и image_size. При задании SQUARE_SIZE в миллиметрах вектор T также выражен в миллиметрах.

В диагностическом выводе базовое расстояние сравнивается с фиксированными **100 мм**. Это значение исходной установки, а не универсальное требование; для своей установки измените диагностическое сравнение. Измеритель берёт геометрию из калибровки.

### 4. Проверьте ректификацию

```powershell
# Windows
python stereo_rectify.py
```

```bash
# Linux
python stereo_rectify_linux.py
```

В окне показываются два выровненных изображения с горизонтальными линиями. Соответствующие точки должны находиться примерно на одной высоте. S сохраняет rect_left.png и rect_right.png без нарисованных направляющих, Q завершает работу. Сохранение заменяет предыдущую пару.

Для численной проверки сохраните пару с полностью видимой шахматной доской:

```powershell
# Windows
python check_rectification.py rect_left.png rect_right.png --cols 9 --rows 6
```

```bash
# Linux
python check_rectification_linux.py rect_left.png rect_right.png --cols 9 --rows 6
```

Проверка выводит среднюю, медианную, RMS и максимальную вертикальную ошибку в пикселях, а также медианную диспаратность. Оценка относится к найденным углам этой пары, а не ко всему полю зрения. Если скрипт предупреждает о возможном обратном порядке углов, сначала проверьте их соответствие визуально.

### 5. Запустите измерение

**Windows:** задайте REAL_DISTANCE_CM в stereo_bm_win.py равным известному расстоянию до объекта в сантиметрах. По умолчанию установлено 100.0.

```powershell
python stereo_bm_win.py
```

**Linux / Raspberry Pi:** реальное расстояние можно передать при запуске; по умолчанию это 60 см.

```bash
python stereo_bm_linux.py --left /dev/video0 --right /dev/video2 --distance 60
```

Дополнительные параметры Linux:

| Параметр        | Назначение                                                 |
| --------------- | ---------------------------------------------------------- |
| --left, --right | Пути к устройствам камер                                   |
| --distance      | Известное расстояние до объекта в см, больше нуля          |
| --calibration   | Путь к файлу NPZ; по умолчанию рядом со скриптом           |
| --results       | Путь к CSV; по умолчанию рядом со скриптом                 |
| --fourcc        | YUYV или MJPG; ограничение текущей реализации описано ниже |

Разместите объект в красной области измерения. Нажмите S: программа соберёт 50 валидных измерений и добавит строку в CSV. Во время сбора держите объект и камеры неподвижными. Q завершает работу; незаконченная серия в CSV не сохраняется.

Клавиши работают в активном окне OpenCV; используйте латинскую раскладку без Shift.

## Установка CREStereo с нуля (Windows 10, NVIDIA RTX 3060)

Ниже описана **фактически использованная конфигурация экспериментов**, а не универсальный вариант для всех видеокарт: Windows 10, Python 3.12, NVIDIA RTX 3060, ONNX Runtime GPU 1.26.0 (CUDA 12 / cuDNN 9), модель `crestereo_combined_iter5_240x320.onnx` с входом **240 × 320**, исходные стереокадры **640 × 480**.

**Сторонний проект:** [ibaiGorordo/ONNX-CREStereo-Depth-Estimation](https://github.com/ibaiGorordo/ONNX-CREStereo-Depth-Estimation) (исходный модуль `crestereo`). Сама нейросеть и сторонняя библиотека не являются авторским кодом данного репозитория. Авторские экспериментальные приёмники и измерители перечислены в `remote_processing/`.

### 1. Клонирование ONNX-CREStereo

Откройте **PowerShell** в корне собственного проекта `Stereo_BM` (при необходимости замените путь на свой):

```powershell
cd "C:\path\to\Stereo_BM"
git clone https://github.com/ibaiGorordo/ONNX-CREStereo-Depth-Estimation.git
cd .\ONNX-CREStereo-Depth-Estimation
```

Если каталог `ONNX-CREStereo-Depth-Estimation` уже существует и был клонирован раньше, **пропустите `git clone`**, просто перейдите в него. Это отдельный сторонний репозиторий, используемый для запуска CREStereo.

### 2. Окружение Python 3.12 и библиотеки

```powershell
py -3.12 -m venv .venv
& ".\.venv\Scripts\python.exe" -m pip install --upgrade pip
& ".\.venv\Scripts\python.exe" -m pip install numpy opencv-python "onnxruntime-gpu[cuda,cudnn]==1.26.0"
```

Версия `1.26.0` и установка CUDA/cuDNN через extras зафиксированы **для воспроизведения выполненного эксперимента**, поскольку более новая `onnxruntime-gpu==1.31.0` на этой машине потребовала CUDA 13 и не загрузила нужные DLL. В других конфигурациях проверяйте [матрицу совместимости ONNX Runtime / CUDA / cuDNN](https://onnxruntime.ai/docs/execution-providers/CUDA-ExecutionProvider.html).

Для работы с USB-камерами и ONNX **не обязательно** запускать `pip install -r requirements.txt` из стороннего репозитория: его примеры могут содержать дополнительные зависимости для YouTube и иных демонстраций. Для приведённых здесь авторских скриптов используются NumPy, OpenCV, ONNX Runtime и модуль `crestereo` из клонированного проекта.

**Проверка библиотек и CUDA-провайдера:**

```powershell
& ".\.venv\Scripts\python.exe" -c "import cv2, numpy, onnxruntime as ort; ort.preload_dlls(directory=''); print('OpenCV:',cv2.__version__); print('ORT:',ort.__version__); print('Providers:',ort.get_available_providers())"
```

В списке должен быть `CUDAExecutionProvider`. Наличие провайдера в этом списке — **предварительная проверка**, а фактическое использование CUDA нужно подтвердить в выводе запуска CREStereo (скрипты печатают `ONNX providers` и прекращают работу при отсутствии CUDA, если явно не разрешён CPU).

При ошибках загрузки библиотек NVIDIA можно проверить драйвер командой `nvidia-smi`. Скрипты `crestereo_live_win.py` и `stereo_receiver_win.py` добавляют каталоги DLL из `site-packages/nvidia` в `PATH` и вызывают `ort.preload_dlls(directory='')` **до создания инференс-сессии**, как это потребовалось в нашем окружении. Подробнее: [официальная документация ONNX Runtime по загрузке DLL](https://onnxruntime.ai/docs/execution-providers/CUDA-ExecutionProvider.html#preload-dlls).

### 3. Получение модели ONNX

Использована **конкретная** модель:

```text
ONNX-CREStereo-Depth-Estimation/
└── models/
    └── crestereo_combined_iter5_240x320.onnx
```

- Источник модели и инструкции по загрузке: [PINTO0309/PINTO_model_zoo — 284_CREStereo](https://github.com/PINTO0309/PINTO_model_zoo/tree/main/284_CREStereo)
- Скачайте из источника вариант **combined / iter5 / 240x320**, извлеките полноценный `.onnx` и положите его в `models/` под указанным именем. Файл модели не поставляется в `Stereo_BM`, автоматически через `git clone` исходного примера он может не появиться.
- Убедитесь, что скачали именно **веса/модель**, а не Git LFS pointer или пустой файл: иначе ONNX Runtime может сообщить `Empty weights data in bin file or bin file cannot be found`.

Проверка на Windows:

```powershell
New-Item -ItemType Directory -Force .\models | Out-Null
Get-Item .\models\crestereo_combined_iter5_240x320.onnx | Select-Object Name,Length
```

Если файл отсутствует, сначала скачайте и поместите модель в папку, затем повторите проверку. Не подставляйте другую модель с иным размером входа без изменения параметров экспериментального кода.

### 4. Размещение собственных Python-скриптов

Пока вы находитесь в папке стороннего проекта, выполните:

```powershell
Copy-Item ..\remote_processing\crestereo_live_win.py .\
Copy-Item ..\remote_processing\stereo_receiver_win.py .\
Copy-Item ..\remote_processing\stereo_bm_receiver_win.py .\
```

Для **прямого** подключения камер нужен `crestereo_live_win.py`. Для **удалённой** обработки `stereo_bm_receiver_win.py` должен лежать рядом с `stereo_receiver_win.py`, так как импортирует из него протокол передачи кадров и ректификацию.

Скрипты ожидают калибровку по пути `..\stereo_project_win\stereo_calibration.npz`. Это должна быть действительная калибровка **тех же физических камер** в правильном порядке LEFT/RIGHT и разрешении `640 × 480`; при другой структуре укажите `--calibration` явно. Калибровку чужой камеры использовать нельзя.

### 5. Запуск CREStereo напрямую с камер ноутбука

Подключите **обе USB-камеры к ноутбуку**, проверьте их индексы (`camera_index_check.py` из `stereo_project_win`), затем выполните из каталога `ONNX-CREStereo-Depth-Estimation`:

```powershell
& ".\.venv\Scripts\python.exe" ".\crestereo_live_win.py" --left 2 --right 1 --distance 50
```

`2` (LEFT) и `1` (RIGHT) — **индексы использованной конфигурации Windows**, а не универсальные значения. Передавать их нужно в том физическом порядке, в котором выполнялась калибровка; неправильная перестановка приводит к ошибочной диспаратности и расстоянию. Если индексы другие, замените `--left` и `--right`. Примеры остальных дистанций:

```powershell
& ".\.venv\Scripts\python.exe" ".\crestereo_live_win.py" --left 2 --right 1 --distance 100
& ".\.venv\Scripts\python.exe" ".\crestereo_live_win.py" --left 2 --right 1 --distance 200
```

Рабочие параметры: `--alpha 1.0`, `--roi-radius 15`, 50 измерений на одну серию, быстрый предварительный прогрев модели на GPU. `--distance` задаёт **эталон** для вычисления ошибки, а не изменяет измеренную глубину. Для первоначальной проверки без эталона параметр `--distance` можно опустить, но тогда `S` не сохранит серию измерений.

**Управление:** щелчок мышью по нужной области **левого** изображения меняет ROI; `S` сохраняет серию из 50 измерений, `P` — кадры и карту диспаратности, `R` — ROI в центр, `Q`/`Esc` — выход.

**Куда сохраняется результат локального запуска:** `ONNX-CREStereo-Depth-Estimation/crestereo_results/crestereo_results_win.csv`; рядом появляются `*_rect_left.png`, `*_rect_right.png`, `*_view.png` и `*_disparity_px.npy`. Новые серии добавляются в CSV.

### 6. Если запуск не удался

| Проблема                                                            | Проверка и решение                                                                                                                                                     |
| ------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `No module named 'cv2'` / `onnxruntime`                             | Запускайте именно `.\.venv\Scripts\python.exe`, установите зависимости **в том же** виртуальном окружении.                                                             |
| `CUDAExecutionProvider` отсутствует                                 | Убедитесь, что установлено `onnxruntime-gpu`, CUDA/cuDNN совместимы и драйвер NVIDIA работает. Не считайте результаты CPU результатами GPU.                            |
| Ошибка `cublas64_13.dll` после установки свежей версии ONNX Runtime | На использованной машине новая версия потребовала CUDA 13; для воспроизведения данного эксперимента установите приведённую выше `onnxruntime-gpu[cuda,cudnn]==1.26.0`. |
| Ошибка `cudnn` / другие DLL на Windows                              | Проверьте CUDA/cuDNN из pip-пакетов и `ort.preload_dlls(directory='')`, а также наличие MSVC Runtime.                                                                  |
| `Model not found` / `Empty weights data`                            | Убедитесь, что `models/crestereo_combined_iter5_240x320.onnx` существует и не является пустым файлом или указателем.                                                   |
| Неверное расстояние или почти нулевая/отрицательная диспаратность   | Сначала проверьте физические LEFT/RIGHT, калибровку, разрешение, правильность ректификации и ROI; не маскируйте перестановку камер модулем диспаратности.              |
| Ошибки `MSMF` или пропуски кадров                                   | Попробуйте прямые USB-порты вместо проблемного хаба, отключите другие приложения с камерами; используйте MJPG.                                                         |

## Удалённая обработка: Raspberry Pi → SSH → ноутбук

Этот режим **не запускает StereoBM или CREStereo на Raspberry Pi**. Raspberry Pi 4B захватывает изображения с двух USB-камер через V4L2, кодирует их в JPEG и отправляет на Windows по запросу. На ноутбуке выполняются ректификация, вычисление диспаратности и оценка расстояния. Захват двух камер реализован программными `grab/retrieve`, без аппаратной синхронизации.

```text
USB-камера LEFT ─┐

### Необходимые файлы

- **На Raspberry Pi:** `stereo_sender_pi.py`.
- **На Windows:** `stereo_receiver_win.py` (предпросмотр и CREStereo) и `stereo_bm_receiver_win.py` (StereoBM). Для локального запуска CREStereo дополнительно нужен `crestereo_live_win.py`. **Именно `stereo_bm_receiver_win.py` импортирует функции из `stereo_receiver_win.py`, поэтому два сетевых приёмника должны находиться рядом.**
- **Общая калибровка:** `stereo_project_win/stereo_calibration.npz`, рассчитанная для тех же **физических** камер, в том же порядке LEFT/RIGHT и при том же разрешении `640 × 480`.
- **Для CREStereo:** файлы внешнего проекта [ONNX-CREStereo-Depth-Estimation](https://github.com/ibaiGorordo/ONNX-CREStereo-Depth-Estimation) и модель `models/crestereo_combined_iter5_240x320.onnx`. Исходная модель и файлы стороннего проекта в данном README не подразумеваются автоматически включёнными в репозиторий.

В использованных тестах два Windows-приёмника размещались в каталоге `Stereo_BM/ONNX-CREStereo-Depth-Estimation/`, то есть **рядом с** `stereo_project_win/`. При таком расположении путь к NPZ и папка модели определяются по умолчанию. Если файлы находятся в других папках, задайте `--calibration` и, для CREStereo, `--model` явно.

### Подготовка

На Raspberry Pi должны работать две камеры; проверьте их индексы для **самой Raspberry Pi**. Индексы Windows не обязаны совпадать. Установите Python 3, OpenCV (`cv2`) и NumPy; для передачи кадров достаточно `cv2`. SSH-сервер на Raspberry Pi должен быть включён, а ноутбук и Pi должны иметь сетевую связь. Рекомендуется стабильная локальная сеть, предпочтительно Ethernet.

Для нейросетевого режима на ноутбуке сначала выполните раздел **«Установка CREStereo с нуля»** выше. Для StereoBM GPU и нейросетевая модель не требуются: достаточно Python, NumPy, OpenCV и двух сетевых приёмников, размещённых в одном каталоге (`stereo_bm_receiver_win.py` импортирует `stereo_receiver_win.py`).

### Передача `stereo_sender_pi.py` на Raspberry Pi

В корне `Stereo_BM` на Windows (замените `piuser` и IP-адрес при использовании на другой машине):

```powershell
scp .\remote_processing\stereo_sender_pi.py piuser@192.168.1.100:~/
```

Проверка на Raspberry Pi:

```bash
whoami
hostname -I
ls -l ~/stereo_sender_pi.py
```

Логин должен быть реальным именем пользователя Raspberry Pi (`whoami`), а не именем пользователя Windows. При `Permission denied` сначала проверьте обычный вход `ssh piuser@192.168.1.100` и пароль пользователя Raspberry Pi. Если применяется ключ SSH, используйте настроенный ключ для `scp`.

Если SSH ещё не включён на Raspberry Pi, используйте `sudo raspi-config` → **Interface Options → SSH → Enable**. Либо проверьте и запустите сервис через терминал Raspberry Pi:

```bash
sudo systemctl enable --now ssh
sudo systemctl status ssh
```

При необходимости на Raspberry Pi OS установите OpenCV и NumPy пакетами системы:

```bash
sudo apt update
sudo apt install python3-opencv python3-numpy
```

Затем убедитесь, что Python видит модуль `cv2`: `python3 -c "import cv2; print(cv2.__version__)"`.

### 1. Передатчик на Raspberry Pi

В терминале Raspberry Pi, где находится `stereo_sender_pi.py`:

```bash
python3 ~/stereo_sender_pi.py --left 0 --right 2
```

`0` и `2` — **пример проверенных индексов в данной установке**, а не универсальные номера. Передатчик по умолчанию открывает порт `127.0.0.1:8765`, работает с кадрами `640 × 480`, запрашивает `25 FPS`, использует MJPG для камер и JPEG с качеством 95 для передачи. Оставьте этот терминал открытым.

### 2. SSH-туннель на Windows

Откройте **отдельный** PowerShell:

```powershell
ssh -N -L 8765:127.0.0.1:8765 piuser@192.168.1.100
```

Замените `piuser` и `192.168.1.100` на логин (`whoami`) и актуальный IP-адрес (`hostname -I`) **вашей** Raspberry Pi. Это пример: подставьте фактические реквизиты своей Raspberry Pi. Введите пароль, если он запрошен. Отсутствие вывода после авторизации — нормальное поведение `ssh -N`; оставьте окно открытым. Сначала выполните шаг 1, затем шаг 2.

### 3. Приёмник на Windows — предварительный просмотр

Откройте **третий** PowerShell в каталоге `ONNX-CREStereo-Depth-Estimation`. Если ещё не сделали это в разделе установки, скопируйте два приёмника из `remote_processing/` в этот каталог:

```powershell
Copy-Item ..\remote_processing\stereo_receiver_win.py .\
Copy-Item ..\remote_processing\stereo_bm_receiver_win.py .\
```

Далее запустите предпросмотр:

```powershell

```

Должны появиться кадры от обеих камер Raspberry Pi после ректификации. Нажмите `Q`, прежде чем запускать другой приёмник: сервер обслуживает одно подключение за раз.

### 4А. StereoBM на Windows CPU

```powershell
& ".\.venv\Scripts\python.exe" ".\stereo_bm_receiver_win.py" --distance 50
```

Испытанные параметры: `--min-disparity 0`, `--num-disparities 256`, `--block-size 15`, `--roi-radius 15`, `--alpha 1.0`. При другой конфигурации их можно переопределить аргументами командной строки.

### 4Б. CREStereo на Windows GPU

```powershell
& ".\.venv\Scripts\python.exe" ".\stereo_receiver_win.py" --mode crestereo --distance 50
```

Не запускайте два приёмника одновременно. Перед началом убедитесь, что программа сообщает `CUDAExecutionProvider`; иначе производительность будет иной или программа остановится. Использован вход модели `320 × 240`, а диспаратность приводится к масштабу исходного кадра `640 × 480`.

Для испытаний на `100` и `200` см измените `--distance 50` на соответствующее эталонное расстояние. **Аргумент `--distance` не подгоняет оценку глубины:** он нужен только для расчёта экспериментальной ошибки.

| Действие                                      | Клавиша / способ             |
| --------------------------------------------- | ---------------------------- |
| Переместить область ROI (31 × 31 пиксель)     | Левый щелчок по левому кадру |

Сохраняются файлы на **ноутбуке**, а не на Raspberry Pi:

```text
ONNX-CREStereo-Depth-Estimation/
└── remote_stereo_results/

    ├── crestereo_pi_offload_win.csv   # серии CREStereo

Не путайте `algorithm_fps` (только StereoBM или инференс CREStereo) с `full_cycle_fps` (полный цикл). `mean_request_to_receive_ms` включает запрос, получение новых кадров, JPEG-кодирование, передачу и декодирование; **это не чистый ping и не только сетевая задержка**.

### Ограничения

- Камеры не синхронизируются аппаратно. Для движущихся объектов будут нужны дополнительные проверки задержки и временного сдвига между кадрами.
- JPEG — формат с потерями, который потенциально влияет на качество сопоставления. Причина различий в точности между конфигурациями этими данными не установлена.
- Положительная диспаратность зависит от правильного физического порядка LEFT/RIGHT. Проверяйте его при переносе камер между Windows и Raspberry Pi; неверный порядок может дать визуально убедительную, но неправильную глубину.
- 100% положительных значений у CREStereo **не равно** 100% правильно сопоставленных пикселей. Для StereoBM `valid_percent` отражает прохождение заданного фильтра в ROI, а не гарантированную точность.
- При изменении калибровки, разрешения или положения камер результаты несопоставимы без проверки ректификации.

## Сравнение экспериментальных конфигураций

| Конфигурация                                          | Обработка           | Полный цикл, FPS | Средняя относительная ошибка |
| ----------------------------------------------------- | ------------------- | ---------------: | ---------------------------: |
| StereoBM, камеры непосредственно к ноутбуку           | CPU ноутбука        |              ≈30 |                       ≈2,37% |
| StereoBM, камеры непосредственно к Raspberry Pi       | CPU Raspberry Pi 4B |             ≈4–9 |                       ≈2,91% |
| CREStereo, камеры непосредственно к ноутбуку          | RTX 3060            |            11,44 |                        3,37% |
| StereoBM, камеры на Raspberry Pi, передача через SSH  | CPU ноутбука        |        **16,06** |                    **3,83%** |
| CREStereo, камеры на Raspberry Pi, передача через SSH | RTX 3060            |         **6,78** |                    **4,42%** |

**Важно:** показатели первых трёх конфигураций взяты из отдельных испытаний, где реальные дистанции могли быть немного иными. Не интерпретируйте таблицу как строгое попарное сравнение на идентичных кадрах. Для сетевых конфигураций исследованы расстояния **50, 100 и 200 см**, по **3 серии × 50 измерений** для каждого расстояния и алгоритма — **450 измерений на алгоритм**.

### Сетевые конфигурации: точность по расстояниям

| Эталонное расстояние             | StereoBM через SSH: измерено / ошибка | CREStereo через SSH: измерено / ошибка |
| -------------------------------- | ------------------------------------- | -------------------------------------- |
| 50 см                            | 51,75 см / 3,51%                      | 51,68 см / 3,36%                       |
| 100 см                           | 102,51 см / 2,51%                     | 103,91 см / 3,91%                      |
| 200 см                           | 210,92 см / 5,46%                     | 211,97 см / 5,98%                      |
| **Средняя относительная ошибка** | **3,83%**                             | **4,42%**                              |

Для сетевого StereoBM доля валидных пикселей ROI на 200 см составила лишь **≈25,81%**, тогда как на 50 см — ≈99,34%, на 100 см — 100%. Поэтому одинаково малая межкадровая вариация результата не означает одинаковой устойчивости сопоставления. При этом CREStereo и StereoBM не обязательно обрабатывали одни и те же области ROI или идентичные кадры; строгое сопоставление точности требует сохранённых одинаковых стереопар.

В сетевых испытаниях **StereoBM обеспечил приблизительно в 2,37 раза больше FPS полного цикла, чем CREStereo** (16,06 против 6,78). Оба алгоритма завышали оценку расстояния на исследованных дистанциях. Ухудшение производительности относительно прямого подключения нельзя приписывать одному SSH: в полном цикле меняются также способ захвата, JPEG-обработка, транспорт и выполнение приёмника.

## Протокол сравнительных испытаний

Для сетевых тестов использованы одни и те же две физические камеры с разрешением 640×480, общая стереокалибровка Windows (`alpha=1.0`, `CALIB_ZERO_DISPARITY`), 50 измерений на серию и по три серии на расстояниях 50, 100 и 200 см. Источник кадров — Raspberry Pi 4B; приёмник и вычисления StereoBM или CREStereo — ноутбук. Канал — JPEG/TCP через локальный SSH-туннель. На 200 см для StereoBM только около 25,81% пикселей выбранной ROI были валидны.

Средние относительные ошибки рассчитаны **сначала по трём сериям на каждом расстоянии, затем по трём расстояниям**. Это не оценка качества по общедоступному стереодатасету и не гарантия работы на произвольных сценах. Для сравнения времени используется **полный цикл**, а не только скорость алгоритма. В `mean_request_to_receive_ms` учитываются запрос/захват/JPEG/транспорт/декодирование, поэтому эту величину нельзя интерпретировать как чистую задержку сети.

## Как вычисляется расстояние

После ректификации StereoBM рассчитывает горизонтальное смещение соответствующих точек — диспаратность. В области 31 × 31 пиксель отбрасываются неподходящие значения. Если осталось не менее 50 пикселей, берётся медиана диспаратности и вычисляется:

```text
Z_cm = f_px × B_mm / (10 × |d_px|)
```

Здесь f — фокусное расстояние из матрицы ректифицированной камеры, B — модуль горизонтальной базы из проекционных матриц, d — медианная диспаратность. Результат представляет глубину вдоль оптической оси ректифицированной камеры.

**Уточнение для нового удалённого режима:** при `cv2.CALIB_ZERO_DISPARITY` смещение главных точек равно нулю, а порядок камер выбирают так, чтобы диспаратность была положительной. В общем случае используется `d - (cx_left - cx_right)`, а не безусловное `abs(d)`: модуль способен скрыть ошибочную перестановку левой и правой камер.

REAL_DISTANCE_CM / --distance используется только для расчёта ошибки эксперимента, а не для настройки измеренной глубины.

### Основные параметры текущего кода

| Параметр                | Windows             | Linux               |
| ----------------------- | ------------------- | ------------------- |
| MIN_DISPARITY           | Проверить в скрипте | Проверить в скрипте |
| NUM_DISPARITIES         | 256                 | 256                 |
| BLOCK_SIZE              | 15                  | 15                  |
| ROI_RADIUS              | 15                  | 15                  |
| MIN_VALID_PIXELS        | 50                  | 50                  |
| NUM_SAMPLES             | 50                  | 50                  |
| Центр области измерения | Центр изображения   | Центр изображения   |

Ранние локальные версии экспериментировали с отрицательной и положительной диспаратностью: актуальные значения для них нужно проверять в исходном коде. **В удалённом StereoBM используется `--min-disparity 0`, `--num-disparities 256`, `--block-size 15`**. Знак диспаратности определяется физическим порядком камер, а не Windows или Linux. При изменении порядка камер проверьте соответствие NPZ, ректификацию и фильтр валидных значений.

## Особенности и устранение проблем

- **Камера не открылась.** Закройте приложения, использующие камеру, повторно проверьте индексы и подключение. В Linux проверьте доступ к нужным устройствам /dev/videoN.
- **Размер кадров не совпадает с калибровкой.** Настройте камеры на разрешение калибровочных снимков либо заново выполните калибровку с нужным разрешением.
- **NO DATA или сбор серии не завершается.** Недостаточно валидных пикселей. Проверьте освещение, резкость, текстуру объекта, качество ректификации, порядок камер и диапазон диспаратности. Однородная поверхность может не давать устойчивых соответствий.
- **Неверный масштаб расстояния.** Проверьте реальный размер клетки и единицы SQUARE_SIZE: измеритель ожидает миллиметры. После изменения положения камер нужна новая калибровка.
- **Не найдена шахматная доска.** Проверьте число внутренних углов, фокус и видимость всей доски на обоих кадрах.
- **Параметр --fourcc в Linux.** Хотя аргумент принимает YUYV и MJPG, далее код повторно устанавливает MJPG. Фактический формат выводится при запуске; для полноценного выбора YUYV потребуется убрать повторную установку MJPG в stereo_bm_linux.py.
- **Область измерения в Windows.** Центр жёстко задан как (320, 240), что соответствует центру изображения 640 × 480. Для другого разрешения скорректируйте center_x и center_y.

Захват использует последовательные grab/retrieve двух камер; аппаратная синхронизация в коде не реализована. Быстрое движение может ухудшать соответствие стереопары.
